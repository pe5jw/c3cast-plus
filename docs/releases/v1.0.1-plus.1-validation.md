# C3CAST-plus 1.0.1-plus.1 release validation

Status: what was and was not checked before this release.

## Automated validation

- Source unit/regression suite: 117 tests passed (`python -m unittest discover -s tests`), 35 of them new in `tests/test_profiles.py`:
  band profiles and LO checks, receiver arguments per profile, MiniTiouner direct mode and LNB supply, RTL-SDR bias-T switching,
  the HackRF plan (signal beside the DC spike and inside the passband at every symbol rate) and commands, receiver assignment,
  Rescan and RX3, and the pages in both profiles.
- The page scripts of both pages, in both profiles, pass a JavaScript syntax check; the receiver settings bar was checked in a
  headless browser (bias-T and HackRF switches visible, hidden for other receivers).
- `hackrf_iq.exe` was cross-built with Zig from the sources in the package (`webapp/receiver/hackrf-iq/build.sh`).

## Source/provenance audit

`tools/build_portable.py` now runs `tools/package_inventory.py` on the finished package folder and makes no zip unless it passes.
It writes `v1.0.1-plus.1-components.json` (in the package and in `docs/releases/`). New compared with C3CAST 1.0.1:
`hackrf_iq.exe` (GPL v2 or later, source `hackrf-iq/hackrf_iq.c`) with libhackrf 2026.01.3 linked in (BSD 3-Clause, source in
`source/libhackrf-2026.01.3/`).

## User acceptance

PE5JW tested the dev build on 2026-11-23 on his own transmission (2405.000 MHz, 500 kS/s, DVB-S2 QPSK 3/4, H.265 1600x900),
all three receivers at the same time: RTL-SDR with a Nooelec Ham It Down and bias-T (Es/N0 18.7 dB, margin +14.7 dB), HackRF One
(Es/N0 23.7 dB, +19.7 dB) and MiniTiouner Express in direct mode (MER 10.4 dB, +6.3 dB). Band settings, receiver assignment,
Rescan, RX3 and the bias-T switch were used.

Not tested on hardware: a PicoTuner with the new assignment, the QO-100 profile with an LNB other than 9750 MHz, two receivers of
the same kind, and the release package on a clean PC. No firmware or transmitter behaviour changed.
